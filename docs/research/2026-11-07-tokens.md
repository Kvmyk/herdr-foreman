# Saving tokens in foreman: research and measurements

As of 2026-11-07. Question: how to reduce token use of the lead and the workers without lowering the quality of the work.

## Measurement of the first attempt (repo with a calculator)

Data from Claude Code logs (`~/.claude/projects/<dir>/*.jsonl`, `usage` field):

| | Turns | Cache reads | Cache writes | Output | Context per turn |
|---|---|---|---|---|---|
| lead (Opus 5.5, xhigh effort) | 67 | 5,166 k | 73 k | 23 k | 44 k to 102 k |
| worker fix1 (Sonnet 5.5) | 6 | 253 k | 17 k | 2 k | 44 k to 46 k |

Findings:

1. **Cost is the number of turns times the context size.** Every turn re-sends the whole context. The lead's tool results were only 67k characters (about 17k tokens), yet cache reads reached 5.2 million.
2. **Half of the lead's calls (29 of 58) were babysitting workers:** `sleep`, reading panels, waiting in the background and reading files with wait results. Each such call is a full turn.
3. **Claude Code's startup alone is about 44k tokens per turn** in interactive mode. In `-p` mode on haiku I measured:

   | Startup | Context per turn |
   |---|---|
   | regular | 25.8k tokens |
   | without MCP servers and skills (`--strict-mcp-config --disable-slash-commands`) | 22.2k |
   | plus only the needed tools (`--tools Bash,Read,Edit,Write,Glob,Grep`) | 13.7k |

   Note (2026-11-08): we no longer use `--disable-slash-commands` in the lean start, because it also disables built-in commands, e.g. `/usage`. The lean start keeps `--strict-mcp-config` and `--tools`.

## What the sources say

1. **Tokens largely translate into quality.** In Anthropic's multi-agent research system, token count explained 80% of the variance in results [1]. What should be cut is waste (repeated context, polling, unused tools), not the thinking the task needs.
2. **Context rules** [2]:
   - tools should return concise information;
   - data is best loaded only when it is needed;
   - subagents should return a condensed summary (usually 1–2k tokens), not their whole work trace.
3. **Prompt caching in Claude Code** [3]:
   - every turn sends the whole context;
   - on a subscription the main context is kept for an hour, with an API key for 5 minutes;
   - changing the model or the tool set mid-session clears the cache;
   - changing the effort level on 5.5 models does not clear it.
4. **Coordination through files** (plan and agreements in files, reading limits, communication outside the conversation) gives, according to practitioners, 70–90% fewer tokens in long runs [4].
5. **Lower effort on simple tasks** gives 20–40% fewer thinking tokens [5].
6. **Team size:** 3–5 workers is the best compromise, because cost grows linearly with the number of workers. Mixing models gives 40–60% savings [6].
7. **Model-generated context files** for agents raise cost by over 20% and slightly lower effectiveness [6]. Precise briefs are better than general repo descriptions.
8. **Data formats:** TOON and Markdown save tokens compared to JSON, but at a risk to accuracy; JSON remains a sensible default choice [7]. The cheapest change is compact JSON without indentation and without superfluous fields.

## What was implemented

| Change | What it helps | Measured effect |
|---|---|---|
| `foreman wait`: one blocking call until the work ends or the first problem; returns the screen tail only on a question | the lead's turn count | in the trial: permission question after 15 s, finish after 3 s, one turn each |
| Lean Claude Code start for the lead and workers (no MCP, skills or unneeded tools; `--full` restores them) | context of every turn | worker: 22.9k instead of 43.6k tokens on the first turn |
| `--effort` on `spawn` (claude, agy) | workers' thinking tokens | the lead picks effort to match the part's difficulty |
| Compact `brief`: only working agents, no sources or superfluous fields, no speech and image models, max 25 models per agent | lead's context until the end of the task | 33k → 9.3k characters |
| Compact JSON in all `--json` output | lead's context | about 30% fewer characters for the same data |
| Lead instructions: combine commands, no polling, precise briefs (files and test command), short reports (up to 10 and up to 5 lines), effort by difficulty | turn count, workers' work | to be checked in the next full trial |
| Reports in the worktree (earlier) | fewer permission questions, so fewer turns | agy stopped asking on every write |

Estimate for a run like the first trial: about 25 turns instead of 67, with a startup context smaller by roughly 20k tokens. That gives about 70% fewer cache reads on the lead's side. This is an estimate, not a measurement; only the next full trial will confirm it.

## What was not done and why

- **The lead's own effort was not lowered.** Planning and review are exactly where thinking pays off, and the lead's output tokens (23k) are a small share of the cost. This can be changed via `leaderArgs` in the config, e.g. `["--effort", "high"]`.
- **The format was not changed to TOON or Markdown,** because the accuracy risk is greater than the gain at a 9k-character brief.
- **No automatically generated repo description was added for workers** (see point 7 in the sources). Instead, briefs name specific files and the test command.
